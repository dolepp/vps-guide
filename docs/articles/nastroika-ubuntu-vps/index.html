Первичная настройка Ubuntu VPS: безопасность за 15 минут

Новый сервер в интернете начинают сканировать боты уже через минуты после выдачи IP. Если оставить вход под root по паролю, рано или поздно подберут. Эта инструкция — минимальный набор, который закрывает 95% типичных проблем. Команды проверены на Ubuntu 22.04/24.04.

1. Подключение и обновление

ssh root@IP_СЕРВЕРА
apt update && apt upgrade -y
timedatectl set-timezone Europe/Moscow

2. Создайте обычного пользователя

adduser deploy
usermod -aG sudo deploy

Работайте под deploy, а root оставьте для экстренных случаев.

3. Настройте вход по SSH-ключу

На своём компьютере (Linux/macOS/Windows PowerShell):

ssh-keygen -t ed25519 -C "my-vps"
ssh-copy-id deploy@IP_СЕРВЕРА

Проверьте, что вход под deploy работает без пароля, прежде чем идти дальше.

4. Отключите вход по паролю и под root

sudo nano /etc/ssh/sshd_config.d/99-hardening.conf
PasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
sudo sshd -t && sudo systemctl restart ssh

Важно: не закрывайте текущую сессию, пока не откроете вторую и не убедитесь, что вход по ключу работает.

5. Файрвол UFW

sudo ufw allow OpenSSH
sudo ufw allow 80,443/tcp
sudo ufw enable
sudo ufw status verbose

Открывайте только те порты, которые нужны. Для WireGuard, например, добавится UDP-порт.

6. fail2ban против подбора паролей

sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd

По умолчанию он банит IP после нескольких неудачных попыток входа.

7. Автоматические обновления безопасности

sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades

8. Swap на маленьком сервере

Если RAM 1 ГБ или меньше, swap спасает от падений при пиках нагрузки:

sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

9. Чек-лист после настройки

  • вход только по ключу, root отключён;
  • UFW включён, открыты только нужные порты;
  • fail2ban запущен;
  • обновления безопасности ставятся автоматически;
  • есть резервная копия важных данных.

Частые вопросы

Безопасно ли отключать вход по паролю?

Да, при условии что вход по SSH-ключу уже проверен. Ключ надёжнее любого пароля и не подбирается ботами.

Нужно ли менять порт SSH?

Не обязательно. Смена порта уменьшает шум в логах, но настоящую защиту дают ключи и fail2ban.

Что делать, если потерял доступ по SSH?

Большинство хостеров дают веб-консоль (VNC) в панели управления, через неё можно исправить конфигурацию SSH.
