Docker на VPS: установка и первый проект на compose

Обновлено: 2026-11-05 · чтение ~2 мин

Docker упрощает развёртывание: приложение, база данных и зависимости упакованы в контейнеры, а переезд на другой сервер занимает минуты. Для комфортной работы с несколькими контейнерами берите VPS от 2 ядер и 2 ГБ RAM.

1. Установка Docker из официального репозитория

sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER

Перезайдите по SSH, чтобы применилась группа, и проверьте: docker run --rm hello-world.

2. Первый проект на docker compose

Пример: веб-сервер Nginx и база PostgreSQL.

mkdir ~/app && cd ~/app
nano compose.yaml
services:
  web:
    image: nginx:stable
    ports:
      - "80:80"
    restart: unless-stopped
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - dbdata:/var/lib/postgresql/data
    restart: unless-stopped
volumes:
  dbdata:
echo 'DB_PASSWORD=придумайте_длинный_пароль' > .env
docker compose up -d
docker compose ps

3. Полезные команды

docker compose logs -f web      # логи
docker compose pull && docker compose up -d   # обновить образы
docker compose down             # остановить
docker stats                    # потребление ресурсов

4. Не забивайте диск

Старые образы и кэш сборки быстро занимают гигабайты:

docker system df
docker system prune -af --volumes   # осторожно: удаляет неиспользуемые тома

Ограничьте размер логов контейнеров в /etc/docker/daemon.json:

{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}

5. Важное про безопасность

  • Docker публикует порты в обход UFW. Привязывайте служебные порты к localhost: "127.0.0.1:5432:5432".
  • Не запускайте контейнеры с --privileged без необходимости.
  • Секреты храните в .env с правами 600, не в репозитории.

Для публикации сайтов используйте обратный прокси: Nginx и Let's Encrypt.

Частые вопросы

Сколько RAM нужно для Docker?

Сам Docker лёгкий, ресурсы зависят от контейнеров. Для пары сервисов с базой данных комфортно от 2 ГБ.

Почему UFW не закрывает порт контейнера?

Docker сам управляет правилами iptables. Публикуйте порты на 127.0.0.1 и выводите наружу только через обратный прокси.
